# 点播同步机制重构：恒基准速度与有界预测定位

日期：2026-10-23。本文替代 `VOD-STABILITY-20261023.md` 中继续采用 ±5% 自动调速的方案；旧文保留为历史证据。

状态更新：2026-10-24，应用已上线，用户已完成 Mac + iPad、Mac + iPhone 点播正常播放的阶段验收；退出/关房后的可用性问题及真实 OBS 直播未验收。下文保留实施时的测试和失败沿革，最新状态以文末“上线与真机里程碑”节为准。

## 目标与边界

解决 iPhone/iPad 正常同步模式下的周期性音画停顿、SYNC 锯齿，以及慢定位留下的初始偏差。保留已经有效的 Host 拖动、服务器未来锚点、鉴权与原片 Range 分发。

不转码；不增加 HAProxy、Coturn、服务、端口或数据库迁移；不改家庭硬盘、Agent、账户、影片或 OBS。最初仅允许本地提交，用户随后明确授权完成后推送与合并仓库。线上仍仅在重新确认空闲后配对更新 App/Worker，Git 合并不豁免该门禁，保留原镜像回滚。

## 证据与因果边界

用户确认两端均未手动修改倍速。17:03:40 的新版 iPhone 录屏中，同一 revision 的 SYNC 从约 1400ms 逐步下降，到接近零时停顿并回升，出现两个完整周期；下降斜率约 50ms/秒，与程序自动 1.05× 追赶吻合。对应视频诊断面板未展开，因此没有手机端逐次 rate 写入或缓冲轨迹，不能声称已经直接测得每次写入的停顿成本。

代码条件模型中，若一次改速损失约 700–750ms 推进，先恢复 1×、再重新切到 1.05× 会形成约 1.4 秒落后和 30–33 秒周期。旧 200/300ms 模型通过不足以覆盖此场景。现在删除这条正常播放执行路径，而非继续调整滞回阈值。

## 实施决策

1. **单一速度来源**：只有 Host 明确选择的基准倍速可以写入 `playbackRate`；正常 1× 不做 1.05×/0.95× 自动追赶。
2. **统一权威时间**：Host 的首个定位仍在服务器锚点生效后执行，所有端走同一逻辑；不提前执行未来指令，不改服务端锚点，不减去虚假的 SYNC 偏置。
3. **实帧确认**：不接受 setter 或 `seeked` 单独证明成功。播放时媒体时钟与实际推进帧均须在目标 250ms 内；暂停容差 150ms。没有帧回调能力时如实标注 unavailable。
4. **有界预测定位**：从本次发出定位到首个推进帧，估算 `损失媒体秒数 = 单调经过秒数 × 基准倍速 − 实际推进媒体秒数`。非负、上限 3 秒 × 基准倍速；下一次定位为当时权威目标加该估计，不累加前次预测。最多三次、总计十秒；同 revision 不重置预算。
5. **自然停顿后的重入**：低缓冲、原生 seeking、无帧推进时不追赶；健康帧和缓冲恢复后，持续超差才能进入一次有界重入。短期再次失败明确提示失同步，要求显式重试或新 Host 指令，不循环跳转。
6. **指令与生命周期隔离**：新权威指令可取代失败或旧 intent；暂停不被旧 error 阻挡。后台和自动播放授权等待不纳入该次耗时预测；旧元素/旧异步结果不能证明新目标完成。预测先到片尾时等待权威到达，禁止 `play()` 从零重启。
7. **就地证据**：显示源码构建 ID；新版本仅提醒，不自动刷新。房间内复制有界、白名单诊断报告，不离开房间、不上传、无身份/凭据/签名地址。HTML、SW 与版本文件 no-store，取消旧 HTML 离线回退。
8. **恢复播放是独立对齐入口**：已完成暂停后的新 Host play，在未来锚点生效时建立 alignment，先等待真实推进帧，再计入启动解码损失；不等几秒后交给稳态 automatic 恢复。播放中重复同速 play 不因此重新定位。

不采用全房间暂停屏障、服务端逐帧调度或 play 截止时刻集合：这些会引入额外 autoplay、网络慢端牵连和协议状态，超出本轮必要范围。预测定位仍可能因设备定位成本剧烈变化而失败；必须有限次失败并保留真实偏差，不能用持续跳转换取短暂归零。

### 用户提出的微调倍速方案

用户补充建议：稳定播放按合理频率采样，落后时 1.01–1.05×、超前时 0.99–0.95×，接近后恢复 1×，容许 ±500ms；Host 也服从服务器时间轴。采纳统一时间轴、双向容差和不因短暂越界立即跳转的目标。初始定位 250ms 是收敛门槛，稳态 ±500ms 是容忍区间，两者不矛盾。

本轮不恢复自动倍速执行器：旧版已经具备双向调速和接近后恢复基准速度，并不存在“禁止超前、接近零就强制拉回”的规则。录屏循环与回到 1× 后的管线扰动相符，但仍缺真机 API 事件因果证据。不转码的服务器只能发送指令，实际调速仍由终端浏览器执行；隐藏倍率不能消除播放器副作用。保留明确 Host 倍速命令，不把“当前 UI 为 1×”误认成旧版底层从未调速。

- 冷定位 1.5 秒转热定位 0.1 秒、成本反复变化、三次/十秒/三秒预算、后台/授权等待、旧指令完成、Host 暂停、预测提前片尾、缓冲饥饿与显式恢复。
- 项目类型、Lint、单元/API/Worker/安全门禁、生产构建；现有真实 HTTPS 三浏览器测试保留鉴权、Range、实际帧、Host 拖动/暂停/恢复及 A/B；补版本与原地报告验证。
- 现有浏览器 fixture 为 H.264 无音轨，本地 WebKit 不是 iOS 真机。它只能证明代码/视频呈现路径，不能证明真实 HEVC/AAC 音画流畅；iPhone/iPad 最终验收单列。
- 发布前两次空闲检查、当前镜像/迁移/来源核对、一致性数据库备份；仅 App/Worker 更新，其他四个容器与受保护数据清单保持不变。
